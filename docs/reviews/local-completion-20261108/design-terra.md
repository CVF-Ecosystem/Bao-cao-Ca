## Design hazards and negative evidence

1. Unsupported/malformed schema, missing or mismatched identity, pre-upgrade backup collision or failed verification must not write source; old version 1.9.2 rejects 4. New binary must never label DB 4 as 3. Full recovery must account for SQLite WAL and crash interruption; no automatic upgrade of existing source or supplied DB.
2. `snapshot` currently calls full validation unconditionally: a quick/full scheduler alone cannot improve latency. Cache is an optimization, never proof previously verified bytes remain uncorrupted; full rehash always detects corruption. Cache binds database identity and invalidates on restore/adoption/migration and detected change; failed full never advances its pin.
3. `apply_corrections` builds preview before target transaction but rechecks payload inside transaction. Preserve recheck and imported revision continuity despite schema gaps; `correction_base` and historical revision references must protect attachments from collection.
4. Retention and file cleanup cross process and symlink/junction boundaries can delete unrelated/user-edited copies. Default to no deletion where identity/type/open-state/export status is uncertain; do not rely on age for editable review copies. Test TOCTOU, interruption, permission/space and restart using disposable fixtures before claims.
5. No source execution or real UI/native print was done in this audit. Roadmap's V1 requires actual Chrome and Edge print dialogs with headers/footers and background options; PDF generated directly by a script does not close it. V2–V8 and business feedback remain separately testable product gates. Baseline after PNI accepted only personnel flow, not U/V or D2–D4.
